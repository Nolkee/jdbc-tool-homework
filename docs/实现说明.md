# 作业1：JDBC工具的设计与开发——实现说明

## 1. 设计思路

本项目用 Java 11、Maven 和 JDBC 实现一个简单的对象关系映射工具 `JDBCTool`。它根据实体类的注解与属性生成 SQL，再通过反射把查询结果转换成 Java 对象。这样，学生表和学院表可以共用一套增删改查代码。

ORM 是 Object Relational Mapping，即对象关系映射。在本作业中，实体类对应数据库表，对象对应表中的一条记录，属性对应记录中的一个字段。例如，一个 `Student` 对象可以保存为 `student` 表中的一行，查询到的一行也可以恢复成一个 `Student` 对象。

本项目保留了 JDBC 的直接使用过程，没有引入 Hibernate、MyBatis 等持久化框架，便于观察 SQL 生成、参数绑定、反射创建对象和属性赋值的步骤。

## 2. 项目各部分的职责

| 部分 | 职责 |
| --- | --- |
| `annotation/Table.java` | 用 `@Table(name = "...")` 指定实体对应的表名。 |
| `annotation/Column.java` | 用 `@Column(name = "...")` 指定属性对应的列名。 |
| `annotation/Id.java` | 用 `@Id` 标记主键属性。 |
| `entity/Student.java`、`entity/College.java` | 保存业务数据，提供无参构造方法和 getter/setter。 |
| `util/JDBCTool.java` | 实现五个通用方法及映射、参数绑定、类型转换等辅助方法。 |
| `util/DatabaseConfig.java` | 读取配置文件，创建数据库连接；支持 H2 和 MySQL。 |
| `util/DatabaseInitializer.java` | 读取 `schema.sql`，创建缺失的两张表，保留已有数据。 |
| `Demo.java` | 调用工具完成两张表的操作，并通过重新查询检查操作结果。 |

默认配置使用 H2 文件数据库，数据库文件位于 `data` 目录，数据库名为 `DateTest`。MySQL 配置对应 `DateTest` 数据库，并提供 `sql/mysql-init.sql` 作为单独的建库建表脚本。数据库用户名、密码和连接地址也可通过 `JDBC_USER`、`JDBC_PASSWORD`、`JDBC_URL` 环境变量指定。

## 3. 实体与表的映射

### 3.1 学生表

`Student` 使用 `@Table(name = "student")` 指定表名。

| Java 属性 | Java 类型 | 数据库列 | SQL 类型 | 含义 |
| --- | --- | --- | --- | --- |
| `id` | `String` | `id` | `VARCHAR(40)`，主键 | 学生编号，标记 `@Id`。 |
| `name` | `String` | `name` | `VARCHAR(80) NOT NULL` | 姓名。 |
| `major` | `String` | `major` | `VARCHAR(80)` | 专业。 |
| `age` | `Integer` | `age` | `INT` | 年龄。 |
| `enrollmentDate` | `LocalDate` | `enrollment_date` | `DATE` | 入学日期，通过 `@Column` 指定列名。 |
| `graduated` | `Boolean` | `graduated` | `BOOLEAN` | 是否毕业。 |
| `tuition` | `BigDecimal` | `tuition` | `DECIMAL(10, 2)` | 学费，保留两位小数。 |

### 3.2 学院表

`College` 使用 `@Table(name = "college")` 指定表名。

| Java 属性 | Java 类型 | 数据库列 | SQL 类型 | 含义 |
| --- | --- | --- | --- | --- |
| `id` | `String` | `id` | `VARCHAR(40)`，主键 | 学院编号，标记 `@Id`。 |
| `name` | `String` | `name` | `VARCHAR(80) NOT NULL` | 学院名称。 |
| `code` | `String` | `code` | `VARCHAR(30)` | 学院代码。 |

没有 `@Column` 时，列名默认取属性名；没有 `@Table` 时，表名默认取类名的小写形式。查询映射时，属性名和列名的匹配不区分大小写，也支持 SQL 的列别名。例如 `enrollment_date` 可以对应带注解的 `enrollmentDate` 属性。下划线命名和驼峰命名之间的对应关系由注解明确表达。

工具会读取当前类及其父类的实例属性，跳过 `static`、`transient` 和编译器生成的属性。每个实体最多允许一个 `@Id` 属性，多个属性不能映射到同一个列名。

两张表的主键都由调用者提供字符串编号，不使用自增主键，也没有自动生成并回填主键的功能。演示程序使用本次运行编号组合出学生和学院的编号，降低重复运行时发生主键冲突的可能性。

## 4. 五个方法的接口与行为

题目开头写“包含四个方法”，随后实际列出了五个方法，因此本项目按列出的五个方法实现。方法都使用泛型 `<T>`，学生对象和学院对象可以使用相同的接口。

```java
public static <T> List<T> resultSetToList(ResultSet rs, Class<T> clazz)
        throws SQLException;

public static <T> int save(T obj, Connection connection)
        throws SQLException;

public static <T> int update(T obj, Connection connection)
        throws SQLException;

public static <T> int delete(T obj, Connection connection)
        throws SQLException;

public static <T> T getOneById(String id, Class<T> clazz, Connection connection)
        throws SQLException;
```

| 方法 | 输入 | 返回值与说明 |
| --- | --- | --- |
| `resultSetToList` | 查询结果集和目标类的 `Class` 对象 | 返回对象列表；没有记录时返回空列表。 |
| `save` | 待保存对象和连接 | 插入对象，返回受影响的行数。 |
| `update` | 含主键及新属性值的对象和连接 | 根据主键更新非主键字段，返回受影响的行数。 |
| `delete` | 含主键的对象和连接 | 根据主键删除记录，返回受影响的行数。 |
| `getOneById` | 主键、目标类和连接 | 返回对应对象；没有记录时返回 `null`。 |

`update` 和 `delete` 必须具有一个 `@Id` 属性，且主键值不能为 `null` 或空白字符串。`getOneById` 同样检查输入主键和实体的主键映射。`save` 在实体声明了 `@Id` 时也会检查主键值。学生和学院实体都声明了 `@Id`，所以调用者保存对象前必须提供有效且未被使用的编号；重复编号会违反数据库的主键约束。

本实现的 `update` 会更新对象的全部非主键属性，包括值为 `null` 的属性。因此实际使用时，可以先用 `getOneById` 获得完整对象，再修改需要变化的属性并调用 `update`。它不是只更新某个字段的局部更新接口。

## 5. ResultSet 到对象列表的转换过程

`resultSetToList` 的处理顺序如下：

1. 检查 `ResultSet` 和目标类，读取实体的表名、列名和可映射属性。
2. 通过 `clazz.getDeclaredConstructor()` 获取无参构造方法，并允许反射访问。
3. 建立“属性名或列名 → `Field`”的映射表。
4. 通过 `ResultSetMetaData` 获取列数量和列标签，提前确定每一列对应的属性。
5. 使用 `rs.next()` 遍历记录，每一行通过无参构造方法创建一个新对象。
6. 使用 `rs.getObject(...)` 读取列值，转换为目标属性需要的类型。
7. 使用 `Field.set(...)` 给对象属性赋值，再把对象加入列表。

列标签使用 `getColumnLabel()` 获取，所以 `SELECT name AS name ...` 这样的查询也能正确参与映射。查询中额外出现但实体没有对应属性的列会被忽略；没有出现在查询结果中的实体属性保持对象初始值。

实体需要无参构造方法，因为通用工具不能预先知道每个实体的有参构造方法及其参数顺序。属性为 `private` 时，通过 `setAccessible(true)` 让反射可以读取和写入它们。创建对象或赋值失败时，工具会转换为带原因的 `SQLException`，便于调用者处理。SQL `NULL` 无法赋给 Java 基本类型，遇到这种情况会抛出异常，提示使用包装类型，避免把空值误当成 `0` 或 `false`。

## 6. SQL 生成与增删改查

下列 SQL 展示当前两种实体生成的语句结构。`?` 表示参数占位符，执行前由 JDBC 绑定对象的实际属性值。

### 6.1 保存

`save` 读取实体的全部可映射属性，生成列名列表和相同数量的占位符，再调用 `executeUpdate()`。

```sql
INSERT INTO student
    (id, name, major, age, enrollment_date, graduated, tuition)
VALUES (?, ?, ?, ?, ?, ?, ?);

INSERT INTO college (id, name, code)
VALUES (?, ?, ?);
```

### 6.2 更新

`update` 将非主键属性放入 `SET` 部分，把主键放入 `WHERE` 条件。主键本身不会被更新。

```sql
UPDATE student
SET name = ?, major = ?, age = ?, enrollment_date = ?,
    graduated = ?, tuition = ?
WHERE id = ?;

UPDATE college
SET name = ?, code = ?
WHERE id = ?;
```

### 6.3 删除

`delete` 只使用对象的主键，不需要使用其他属性。空主键会在执行 SQL 前被拒绝。

```sql
DELETE FROM student WHERE id = ?;
DELETE FROM college WHERE id = ?;
```

### 6.4 按主键查询

`getOneById` 执行查询后调用 `resultSetToList`，取第一条结果；没有结果时返回 `null`。由于数据库主键唯一，正常情况下最多查询到一条记录。

```sql
SELECT * FROM student WHERE id = ?;
SELECT * FROM college WHERE id = ?;
```

### 6.5 列表查询与对象映射

`resultSetToList` 只转换结果集，不负责生成列表查询的 SQL。调用者可根据业务需要执行查询，再把 `ResultSet` 交给它。例如演示程序仅查询本次插入的两条记录：

```sql
SELECT * FROM student WHERE id IN (?, ?) ORDER BY id;
SELECT * FROM college WHERE id IN (?, ?) ORDER BY id;
```

工具根据同一份属性列表生成列名、占位符并绑定参数，因此列和参数保持对应。实现不依赖反射返回字段的顺序必须固定。

## 7. PreparedStatement 与类型处理

数据值通过 `PreparedStatement` 的参数绑定方法传入，不直接拼接进 SQL。例如姓名含有单引号时，它仍会作为姓名数据处理，而不会改变 SQL 的结构。这可以避免通过数据值进行 SQL 注入。

表名和列名无法使用 `?` 参数绑定，所以它们来自实体映射，并由工具检查是否符合 `[A-Za-z_][A-Za-z0-9_]*`。带空格、引号或分号的非法标识符会被拒绝。

本作业主要处理以下类型：

| 数据 | 写入过程 | 读取过程与原因 |
| --- | --- | --- |
| 入学日期 | `LocalDate` 转成 `java.sql.Date`，使用 `setDate()`。 | 将 JDBC 日期转换回 `LocalDate`，只保存年月日。 |
| 是否毕业 | `Boolean` 通过 `setObject()` 交给驱动。 | 支持布尔值、数值 `0/1` 和字符串 `false/true`、`0/1` 转换。 |
| 学费 | `BigDecimal` 通过 `setObject()` 绑定。 | 使用 `BigDecimal` 与 `DECIMAL(10,2)` 对应，避免用二进制浮点数表示金额的误差。 |
| 年龄 | `Integer` 通过 `setObject()` 绑定。 | 数据库返回数值后转换为 `Integer`。 |
| 空值 | 由 JDBC 处理 `null`。 | 包装类型可以接收 `null`；基本类型遇到 SQL `NULL` 时抛出 `SQLException`，提示使用包装类型。 |

演示中的金额使用 `new BigDecimal("5800.00")` 这样的字符串构造方式，避免先经过 `double`。比较金额时使用 `compareTo()`，因为 `5800.0` 和 `5800.00` 数值相同，但小数位数不同。

## 8. 连接、资源与事务

数据库连接由调用者创建、传入并关闭。`JDBCTool` 不在每次操作时重新创建连接，也不会自行关闭调用者传入的连接，因此多次操作可以共享同一个事务。

资源的关闭范围如下：

| 资源 | 负责关闭的一方 |
| --- | --- |
| `Connection` | 创建连接的调用者。演示程序使用 `try-with-resources`。 |
| `save`、`update`、`delete` 创建的 `PreparedStatement` | 对应工具方法。 |
| `getOneById` 创建的 `PreparedStatement` 和 `ResultSet` | `getOneById` 方法。 |
| 调用者传给 `resultSetToList` 的 `ResultSet` | 调用者；映射方法只读取，不关闭它。 |

演示程序先初始化表，再关闭自动提交：`connection.setAutoCommit(false)`。随后在同一连接上执行两张表的增删改查。操作成功后调用 `commit()`；出现异常时调用 `rollback()`，然后继续抛出异常。这样，提交或回滚的决定由调用者统一作出，而不是由工具的单个方法作出。

每次演示使用独立编号，保存两名学生和两个学院，读取对象列表，按主键查询，修改其中一条，再删除另一条，最后重新查询检查。初始化语句使用 `CREATE TABLE IF NOT EXISTS`，不会清空原有表。文档描述的是代码设计与调用流程；实际运行结果应以提交的运行截图和执行日志为准，MySQL 是否运行通过也应以实际连接与执行结果为准。

## 9. 可能的课堂提问

**问题1：为什么这是 ORM？**

答：它把类与表、属性与列、对象与记录建立了对应关系，并自动完成对象写入数据库和记录转换成对象的过程。

**问题2：为什么需要 `Class<T> clazz`？**

答：泛型主要在编译时检查类型，工具还需要目标类的运行时信息，才能获取构造方法和属性，通过反射创建并填充对象。

**问题3：属性名和数据库列名不一样怎么办？**

答：使用 `@Column` 指定列名，例如 `enrollmentDate` 映射到 `enrollment_date`。表名不同时用 `@Table` 指定。

**问题4：为什么 `update`、`delete` 必须使用主键条件？**

答：主键可以唯一确定记录。工具根据 `@Id` 生成 `WHERE`，并拒绝空主键，避免错误地生成没有定位条件的更新或删除。

**问题5：为什么学费用 `BigDecimal`，不用 `double`？**

答：学费是金额，需要准确的十进制表示。`double` 可能出现二进制浮点误差，`BigDecimal` 更适合与数据库的 `DECIMAL` 对应。

**问题6：为什么工具不自己关闭连接和提交事务？**

答：一次业务可能包含多个操作，调用者需要让它们共用连接，成功时一起提交，失败时一起回滚。工具只关闭自己创建的语句和结果集。
